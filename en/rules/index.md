## Contributing Rules

New rules are welcome — new cloud-provider credentials, PII types, component / packer signatures, sensitive permissions, etc. Two ways to submit:

1. **Issue (recommended)**: open an issue with the [rule submission template](https://github.com/kelvinBen/AppInfoScanner-Site/issues/new?template=rule-submission.md) — category, regex, rationale and test cases.
2. **Direct PR**: edit [`shared/community-rules.ts`](https://github.com/kelvinBen/AppInfoScanner-Site/blob/main/shared/community-rules.ts) in the site repo and append entries following the in-file example.

**Requirements** (review criteria):

- Python `re` syntax, same as the program; provide both a **should-match** and a **should-NOT-match** sample to avoid false positives.
- Credential / PII rules need a rationale (official docs, public format spec, or real samples).
- Component / packer rules need the package identifier (or binary marker) plus a risk note; attach the CVE id and safe version when available.

Once merged, rules appear in the "Community Rules" section above; durable ones get baked into the built-in config with the next program release and synced back to the official list.
